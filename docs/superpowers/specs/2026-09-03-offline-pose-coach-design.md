# 本机离线羽毛球姿势教练（第一期）设计

日期：2026-09-03  
状态：待用户审阅  
范围：PC 本机、侧面机位、后场击球（含反手高远）

## 1. 背景与目标

在本机分析用户录制的羽毛球练习视频：识别人体姿势，与规则化「标准」及可选示范视频对比，给出中文改进意见。

后期（不在本文范围）：实时捕捉、羽毛球落点与球路、战术建议、Android / iOS。第一期把分析做成本机 HTTP API，便于以后被 App 复用。

本机条件：Windows，NVIDIA GTX 1070（8GB）、i9-13900K、32GB RAM、Python 3.11 / 3.12。GitHub 访问不稳定，依赖与模型走国内镜像或本地 `models/` 缓存。

## 2. 第一期要做什么 / 不做什么

**要做**

- 本机网页上传整段侧面练习视频（数分钟、多次击球），自动切出每一次挥拍并评分。
- 后场四种类型：正手高远、杀球、吊球、反手高远。上传时指定整段默认类型；列表里可改某一次的类型后只重评分。
- 标准 = 生物力学规则打分 + 可选示范视频骨架对齐对比。没有示范时规则评分仍完整可用。
- 画面多人时自动选出正在击球的人，网页可改选。
- 改进意见用中文模板填空；预留以后换大模型润色的接口，第一期不接大模型。
- 持拍手在上传时选择，默认右手。

**不做**

- 实时摄像头、球追踪 / 落点 / 球路、自动区分杀球与吊球、背面 / 场边机位。
- 网前、步法、发球的规则包（架构预留，第一期不实现）。
- 手机 App、登录、云同步。
- 第一期不以「建议已经像真人教练一样准」为通关条件；阈值用真实视频再标定。

## 3. 技术路线

采用 MediaPipe Pose + 规则引擎 + FastAPI + 薄前端。姿态估计做成可替换接口，以后可换成 YOLO-Pose，不在第一期做。

不采用 MMPose + TrackNet 全家桶：那是后期球与战术的方向，对「姿势对不对」帮助有限，且依赖下载成本高。

## 4. 架构

本机进程：FastAPI 提供 API 与静态网页。浏览器只负责上传、点选、展示；识别与分析全在 Python。

可替换单元（彼此只传骨架序列、击球片段、评分结果）：

| 单元 | 职责 | 第一期实现 | 以后可换 |
|------|------|------------|----------|
| 姿态估计 | 每帧人体关键点 | MediaPipe Pose（33 点，含估计深度） | YOLO-Pose |
| 人物选择 | 多人中选出练习者 | 体型 + 位置 + 手腕速度，可手选 | 稳定追踪 ID |
| 击球切割 | 整段切成每一次挥拍 | 持拍手手腕速度峰值 + 关键帧扩窗 | 学习式分割 |
| 技术规则 | 按类型打分 | 后场规则包（四种） | 网前 / 步法 / 发球；其它机位 |
| 建议生成 | 中文改进意见 | 模板填空 | 大模型润色 |
| 示范对齐 | 与示范视频对比 | 骨架序列 DTW（可选） | 更精细相位对齐 |
| 任务存储 | 视频与结果 | `data/jobs/<job_id>/` 下的文件 | 数据库 |

机位作为规则包参数传入。第一期只实现 `side`。Python 使用 3.11。

分析为异步任务：上传立即返回 `job_id`，后台抽帧、骨架、切割、评分；网页轮询进度。

## 5. 数据流

1. **上传**  
   用户提交：练习视频、整段默认动作类型、持拍手、机位（第一期固定 `side`）、可选示范视频。原视频存为 `data/jobs/<job_id>/input.mp4`，立即返回 `job_id`。

2. **抽骨架（每任务只做一次）**  
   使用 MediaPipe Pose Landmarker，每帧最多检测 4 人，按帧、按人写出 `poses.jsonl`（33 点的 x, y, z, visibility）。人物改选、类型改选、重新评分都不再跑模型。

3. **选人**  
   默认 `person_id` 写入 `job.json`。网页改选后从第 4 步重跑。

4. **切击球**  
   对选定的人切片段，每段带上默认技术类型。

5. **评分 + 建议**  
   关键帧关节角与时序套入对应规则包 → 分项分、总分、模板建议。改某一击类型只重跑该片段规则。

6. **可选示范对比**  
   示范视频同样抽骨架并自动切击球。第一期不提供「框选示范片段」：取置信度最高的一次示范击球作为模板，每一拍练习与该模板做 DTW，输出关节角差。示范失败、缺失或切出 0 次则跳过，不影响步骤 5。

7. **展示**  
   `GET /jobs/{id}` 返回进度、击球列表、单条详情（角度、分项、建议、示范差）。骨架缓存与评分结果落盘；关闭浏览器再打开同一任务不重算。

任务状态：`queued` → `extracting_pose` → `segmenting` → `scoring` → `done`，或 `error`。

## 6. 击球切割

上传时选择持拍手（默认右）。侧面后场用持拍手手腕速度作为主信号；反手高远仍看同一只手，只换规则包。

算法：

1. 计算持拍手手腕逐帧速度，平滑去抖动。
2. 速度峰值作为击球瞬间候选。两次峰值间隔小于约 0.7 秒时只保留更高者。
3. 每个峰值向前扩展引拍（手腕后摆、肘屈曲），向后扩展随挥（速度回落）。用速度谷和肩—肘—腕几何收边，不使用固定帧长。典型后场一次约 0.8–1.5 秒。
4. 丢弃峰值过低、手臂未上举、或可见度过差的候选。每段给出切割置信度。
5. 网页按时间列出片段；低置信度标出。第一期支持删除误切，不支持在时间轴上手工再画一段。需要补切时，将漏掉的部分另存为视频再传。

喂多球节奏快时阈值偏松：宁可多切让用户删，也不漏真正击球。第一期不自动区分高远 / 杀 / 吊，也不自动判正手 / 反手。

改选人后重新切割并评分（读骨架缓存）。改某一击类型不重新切割。

## 7. 后场规则包与建议

每一击输出分项分（0–100）与加权总分。明显偏离目标区间的项触发中文模板，每击最多 3–5 条建议。规则放在 YAML 中，改阈值不必改代码。第一期阈值为文献与常识初值，用真实视频标定。

侧面 MediaPipe **用于评分的量**：膝角、肘角、击球点相对头 / 肩的高度、躯干前倾或后仰、持拍手手腕速度、肩→肘→腕速度峰先后顺序。

**第一期不评分**：拍面、握拍、球速、落点、前臂内旋。髋转仅作弱参考，不作为硬条件。

| 类型（代码） | 更看重 | 典型建议触发 |
|--------------|--------|----------------|
| `forehand_clear` 正手高远 | 击球点高、肘较充分伸展、蹬地后手臂再加速 | 击球点偏低；肘未打开就发力；只有手臂没有腿 |
| `smash` 杀球 | 更明显屈膝蹬伸、躯干鞭打、非持拍手配合、手腕峰值更高 | 像推球没有下压准备；非持拍手下垂；击球点偏前偏低 |
| `drop` 吊球 | 引拍可接近杀球，击球段手腕峰值与随挥明显更小 | 随挥过大（更像抽 / 杀）；引拍太短、没有欺骗性 |
| `backhand_clear` 反手高远 | 肘抬高、击球点在头侧后方、靠前臂伸展而非硬抡肩 | 肘塌、击球点过低；转身不够、用正手方式够反手 |

杀与吊在姿势上接近，类型以用户指定（可改正）为准。指定错误则分数和建议会错。

示范对比不替代规则：规则回答是否合格，示范回答与该次示范差在哪个角、哪一帧。两者同时显示。

建议生成器接口：输入结构化「问题列表 + 数值」，输出字符串列表。第一期实现为模板；以后可换成大模型，调用方不改。

## 8. 本机网页

单显示器、浏览器一个窗口。两个页面（不是两台显示器）：

**页面 1 — 新建分析 + 历史**

- 上半：上传练习视频；整段动作类型（正手高远 / 杀 / 吊 / 反手高远）；持拍手（默认右）；机位锁定「侧面」（显示但不可改）；示范视频可选。提交后进入页面 2。
- 下半：历史任务列表，点开进入页面 2 查看已有结果。

**页面 2 — 任务结果**

- 左：击球列表（时间码、类型、总分、切割置信度）。可删除误切；可改某一次类型（只重评分）。
- 中：播放器。点某一击跳到该片段，叠加骨架与关键角度，「只看这一击」循环。多人时可改选分析对象（重切 + 重评，不重抽骨架）。有示范时可切换并排：练习 | 示范，DTW 对齐后同步 scrub。
- 右：总分、分项条、最多 3–5 条中文建议。有示范时列出主要关节角差。

无登录、无云同步。桌面浏览器为主。结果页为同一窗口内三栏，不是多块物理屏幕。

## 9. 失败与边界

出错时任务为 `error`，网页显示中文原因和可采取的动作；英文堆栈只写后台日志。

| 情况 | 处理 |
|------|------|
| 视频打不开 / 编码不支持 | 提示改用 MP4（H.264）。第一期不保证全部手机编码 |
| 全程检测不到人 | 失败，提示人要完整入画、光线足够、不要过远 |
| 部分帧丢骨架 | 短缺口插值；连续丢失过多则该段降置信度或丢弃该击 |
| 切出 0 次击球 | 任务仍为 `done`，列表为空，提示检查持拍手、是否侧面挥拍 |
| 多人选错 | 不算失败；结果页改选人后重切 |
| 示范视频失败 | 不影响练习视频规则评分；关闭并排并说明原因 |
| 显存不足 / MediaPipe 崩溃 | 自动改 CPU 重试一次；仍失败则 `error`。若 `poses.jsonl` 已部分或全部写入则保留。用户可点「重试」：有完整骨架则从切割继续，否则从抽骨架继续 |
| 关闭浏览器 | 后台继续；再打开同一任务看进度或结果 |

上传建议限制：文件不超过 1GB，建议 1080p、30–60fps。超长视频不拒绝，进度必须持续更新。

## 10. 存储与接口（实现约束）

目录：

```
data/jobs/<job_id>/
  input.mp4
  demo.mp4            # 可选
  poses.jsonl
  demo_poses.jsonl    # 可选
  job.json            # 状态、选人、类型、持拍手
  strokes.json        # 切割与评分结果
```

API（第一期）：

- `POST /jobs` 创建任务（multipart）
- `GET /jobs` 历史列表
- `GET /jobs/{id}` 状态与结果
- `POST /jobs/{id}/person` 改选人并重切评分
- `POST /jobs/{id}/strokes/{stroke_id}/type` 改类型并重评分
- `DELETE /jobs/{id}/strokes/{stroke_id}` 删除误切
- `POST /jobs/{id}/retry` 从上一成功阶段续跑
- `GET /jobs/{id}/video` 练习视频文件（浏览器播放）
- `GET /jobs/{id}/demo-video` 示范视频（若有）
- `GET /jobs/{id}/poses?from_frame=&to_frame=` 按帧范围取关键点，避免一次加载整段 jsonl

视频片段用原视频 + 时间码在浏览器播放，不为每一击另导出文件。叠加骨架由前端根据当前帧关键点绘制，后端不生成带骨架的预览视频。

## 11. 验收

**自动测试（无真实视频）**

- 规则引擎：人造骨架序列上，四种类型打出预期分项和对应中文建议。
- 切割：手腕速度中埋入峰值，切出正确次数与大致时间；过近峰值合并。
- API：创建、查进度、改类型、改选人、删除误切。
- 示范失败不影响主评分。

**本机手工（用户侧面后场视频）**

- 打开本地页，上传整段练习，选类型与持拍手，进度能走到完成。
- 列表有多次击球；点开能跳转片段、看到骨架与角度、总分与 3–5 条中文建议。
- 改某一击类型后分数和建议更新，不重抽骨架。
- 多人画面可改选人并重切。
- 有示范时可并排 scrub；无示范或示范损坏时规则结果仍在。
- 关闭浏览器再打开同一任务，结果仍在。

分数是否像教练不作为第一期通关条件。

## 12. 以后怎么接（不在本期实现）
